Abstract
The current BusyLean champion is a single reflection step over a kindpolymorphic extension of System 𝐹𝜔 , seeded by the preceding contender’s
function. This memorandum proposes a substantially stronger, still constructive successor. First, it turns kind-polymorphic reflection into a family-aware
operator: an object-language program can address a dynamically selected
member of an oracle family. Second, it lifts an arbitrary family operator along
the repository’s existing self-indexing 𝑊-tree, which contains every 𝑊-tree
definable by the earlier object language. Third, it iterates that autonomous lift
at the meta-level. At input 𝑛, the selected ramification rank is one more than
the value of the entire Contender 10 family at 𝑛.

A mere definition 𝐺(𝑛) + 1 would violate the spirit of the contest. Here the previous
construction is used in the same legitimate way as in accepted entries—as an
oracle family and as a schedule—but the new mechanism is an operator hierarchy.

applies a complete rank-one autonomous hierarchy to its family of child results.
Rank 𝑟 + 1 therefore reflects the entire rank-𝑟 operator.

7 Why the numerical jump is substantial
7.1 Three independent amplifiers
There are three conceptually separate sources of growth.
Stronger oracle interface. The base reflector does not receive merely one
unary oracle value at the current input. Through pairing it exposes a countable
family, allowing an object-language program to compute both the family index and
the argument.
Autonomous transfinite-shaped traversal. Rank one lifts kind-polymorphic
reflection along I. That tree was built to join every 𝑊-tree definable in the earlier
language. This is not a fixed-height loop; its recursion follows a higher-type
inductive object.
Meta-level ramification. Successor rank does not add one more object-language
program. It turns the entire previous operator into the node operator of a fresh
traversal of I. Finally, the rank is not fixed externally: it is 𝐺(𝑛) + 1.

8 Computability and constructivity
8.1 Totality of every layer
The construction is computable in the ordinary, extensional sense: there is a total
algorithm that returns its natural-number value, although no feasible physical
process could execute it for the contest input.
1. Fk.ctmsUpTo n is a finite list generated by primitive recursion.
2. Type inference uses finite fuel. Accepted terms are strongly normalizing by the
inherited theorem Fk.sn_of_typed.
3. Fk.fvalue therefore computes a normal form and decodes a natural number
using a total function.
4. Prefix and list maxima are total primitive-recursive operations.
5. RK.lift recurses structurally on an inductive 𝑊-tree, using the same recursion
pattern as accepted repository code.
6. RK.ramified recurses structurally on a natural-number rank.
7. The rank 𝐺(𝑛) + 1 is itself the output of a total prior construction.
Closure of total computable functions under composition and structural recursion
yields total computability of 𝐹11 and 𝐶11 .

8.2 Why non-feasibility is irrelevant
“Computable in principle” does not mean “practically evaluable.” Even the existing
contenders are deliberately never evaluated. Kernel checking verifies types and
proofs about symbolic definitions; it need not normalize the final natural number.
The proposed rank is itself an uncomputably large practical task while remaining
a perfectly computable mathematical natural number.

11 Adversarial review
11.1 Objection: the prefix maximum makes the proof trivial
The local inequality is intentionally trivial. Reflection constructions are useful precisely because a simple maximum packages the values of an entire finite language
enumeration. The scientific content lies in what is placed under that maximum,
how the oracle family is exposed, and how the reflector is iterated. Removing the
explicit maximum would complicate the comparison without making the number
conceptually larger.

11.2 Objection: using 𝐺(𝑛) as the rank is lazy
The rule prohibits mentioning the prior constant and adding a margin; it permits
using the previous construction as an oracle or seed in a qualitatively stronger
mechanism. This proposal satisfies the stronger test that its new rank hierarchy
exists independently of 𝐺: for each 𝑟, R𝑘𝑟 is a separately defined operator, and
successor ranks are formally strict. Moreover R𝑘1 (𝐺,̄ 𝑛) already represents a
genuine autonomous kind-reflection construction. Choosing rank 𝐺(𝑛) + 1 is an
amplifier applied to that new mechanism, not its sole source of superiority.

11.3 Objection: recursion at a gigantic rank may fail the build
budget
Elaboration and kernel checking do not evaluate the variable expression 𝐺(𝑛)+1 to
choose recursion branches. The definition of ramified is a small structural recursor.

12 Further research directions
1. Kernel validation and minimization. Compile on Lean 4.34.0, repair only
elaboration-level issues, measure clean phases, and reduce proof dependencies
if the closure or timing is unexpectedly large.
2. A rank indexed by definable trees. Replace the natural rank with an inductive
meta-index whose constructors themselves are drawn from the self-indexing
𝑊-language. This would turn finite ramification into a genuinely transfinite
operator hierarchy.
3. Internalized operator codes. Define a total object language that codes family

operators rather than defining the hierarchy only in the Lean metalanguage.
4. Predicative kind-universe ladder. Extend the current kind system with a
stratified sequence of kind universes, retaining normalization and decidable
checking. The DRKR amplifier can then be applied to each level.
5. Large elimination. Investigate an object language with inductive families and

the current separation between the 𝐹𝑘 language and the older 𝑊-language.

theorem for index, then determine whether autonomous operator lifting corresponds to ordinal multiplication, exponentiation, a collapsing operation, or a

reliance on the prefix guard for quantitative comparisons.

ramification theorems as a reusable module parameterized by an operator and
an index path.
