Abstract
At the pinned revision 4c4b03d0e2003c479e3bee90a21c8bea13f66c40, the current BusyLean
entry is Contender 10, obtained by reflecting a kind-polymorphic extension of System Fω over
Contender 9’s numerical family. This article proposes a structurally stronger, still constructive
entry. First, the unary oracle of Contender 10 is lifted back to a countable family by the repository’s
certified 2-adic pairing. Second, the resulting kind-polymorphic reflector is installed at every node
of a well-founded W -tree. Third, the forest is run along the repository’s self-generated tree index,
which joins every W N tree denoted by the earlier W-language. Finally, an input-diagonal “crown”
of n + 1 additional reflection nodes is placed above that index.
The proposed family is

family10 (n) = F10 (F10 (n)),
F11 (n) = Sfamily10 Crownn+1 (I), n ,
and the proposed closed number is
C11 = F11 (F11 (42)).
The comparison is exact and needs no ordinal calibration: family10 (n) < F11 (n) for every n, hence
C10 = family10 (42) < C11 . Stronger structural statements show that every crown edge is strict,
every accepted depth-bounded kind-polymorphic program at the root is exceeded, and every tree
denoted by the old W-language is eventually dominated.
The package supplies Lean modules, an axiom/dependency audit, integration tooling, a finite
independent reference model, and reproducibility evidence. The packaging environment did not
contain Lean 4.34.0 or lake; therefore the formal files are a concrete kernel-checkable proposal,
not a claim of a completed kernel build. Static auditing and 670 finite structural checks pass; the
remaining certification and timing obligations are stated explicitly.

Certification status. The mathematical comparison and the proposed Lean proof are given
in full. The PDF, source audit, package hashes, and finite reference tests were produced in the
present environment. Lean elaboration, #print axioms, transitive closure checking, and the
15/60 second budgets remain to be run in a pinned Lean 4.34.0 checkout. Nothing in this article
should be read as silently substituting Python tests for the Lean kernel.

The actual baseline

The target is not the original Coq Contender 5 and not one of the earlier unmerged proposals. The
inspected BusyLean revision is 4c4b03d0e2003c479e3bee90a21c8bea13f66c40. At that revision, the

and proves contender_9_lt_contender_10. The reflected object language is a kind-polymorphic
extension of System Fω with a total normalizer justified by reducibility candidates. A bounded syntax
list and a sound checker make its finite numerical maximum a computable natural number.
Contender 10 is already a substantial entry. A serious successor must not merely add one, multiply
by a fixed constant, or repeat the named scalar. The new construction below changes the shape of
reflection: the stronger object language is reflected at every node of a well-founded forest, and the
forest is traversed through a self-generated index plus a diagonal crown.

1.2

Contest obligations

The repository rules impose five constraints that matter directly here.
1. The result must be a closed computable Nat. Uncomputable Busy Beaver functions, noncomputable,
partial, unsafe, external implementations, and opaque placeholders are excluded.
2. The comparison with the preceding entry must be a formal strict inequality.
3. The permitted axiom envelope is the one already used by BusyLean: propext and Quot.sound;
classical choice and custom axioms are excluded.
4. The new definition and proof phases have separate 15-second and 60-second budgets once the
accepted predecessor is precompiled.
5. The named scalar contender_10 may not be used as a shortcut. Reusing the preceding construction
as an oracle family is permitted when it is embedded in a qualitatively stronger construction.
The proposed source is organized around these constraints. The definition module imports only the
previous definition module. It defines the old construction uniformly as family10 n := F10 (F10 n),
but its executable syntax contains no occurrence of contender_10. The proof and audit are separate
modules.

The inherited semantic interfaces

2.1

Kind-polymorphic reflection

Write Vf (n, t) for Fk.fvalue f n t: type-check t with fuel n; if its type is the Church numeral type,
erase and normalize it relative to the unary oracle f , then decode the normal form; otherwise return
zero. Let Tn be the finite list Fk.ctmsUpTo n. Contender 10 uses




R10 (f, n) = n + 1 + max f (n), max Vf (n, t) .
t∈Tn

The repository proves three facts that are crucial for reuse:
1. the checker is sound;
2. checked terms erase to strongly normalizing terms;
3. R10 (f, n) exceeds both f (n) and every listed program value.
The proposed successor does not alter the object language, checker, normalizer, or decoder. It changes
the oracle interface from one function to a countable family and then iterates that reflection through a
W -tree.

2.2

Packing a family into one unary oracle

For k > 0, write uniquely

k = 2i (2m + 1).

The repository’s functions v2, unpair2, and packFamily implement
code(i, m) = 2i (2m + 1),

pack(f )(k) = f (unpair2 (k)).

It proves the exact decoder theorem
unpair2 (2i (2m + 1)) = (i, m),
so

pack(f )(2i (2m + 1)) = f (i, m).

This matters because a kind-polymorphic program at a forest node can call any child i at any numerical
input m using an ordinary unary oracle call. No uncomputable family oracle is introduced.

def reflect11 (fs : W.Family) (n : Nat) : Nat :=
n + 1 + BigNumber.maxN (W.prefixMax (fun i => fs i n) n)
(BigNumber.maximum (Fk.fvalue (packFamily fs) n)

Every operation in this expression is total. The two maxima are over finite lists or finite prefixes. The
only potentially subtle component is Fk.fvalue, whose totality is inherited from the formal strong
normalization theorem.
Lemma 3.2 (Visible child bound). If i ≤ n, then f (i, n) < R11 (f, n).
Proof. The prefix maximum is at least f (i, n). It is at most the outer maximum, and R11 adds n + 1,
which is positive.
Lemma 3.3 (Program bound). If t ∈ Tn , then
Vpack(f ) (n, t) < R11 (f, n).
Proof. The listed program value is at most the finite program maximum, hence at most the outer
maximum. Again the positive summand makes the inequality strict.
Lemma 3.4 (Input bound). For every f, n, n < R11 (f, n).
Proof. R11 (f, n) = n + 1 + M for a natural number M .
These lemmas are deliberately order-free in the oracle. Reflection is not monotone in an arbitrary
oracle: a program may inspect an oracle result and branch in an anti-monotone way. All comparisons
in this package therefore use explicit inclusion—a child occurs in the finite prefix, or a program occurs
in the finite syntax list—rather than a false monotonicity principle.

5.2

Why the height is input-diagonal

A fixed crown of height 43 would strengthen the scalar at input 42 but would not define a uniformly
expanding family. We instead use height n + 1. This has three benefits.
1. The uniform theorem records a growing number of explicit semantic reflection levels, not a hardcoded scalar embellishment.
2. At the advertised inner input 42, there are exactly 43 strict crown edges above the self-generated
index.
3. At the outer input F11 (42), the closed contender traverses F11 (42) + 1 fresh crown edges. This is a
diagonal amplification whose height is itself already the new family value.
The crown is not the only source of growth: beneath it lies the entire self-generated forest. Its purpose
is to provide a clean, exact, inspectable margin in addition to the more complex forest semantics.

Exact comparison with Contender 10

7.1

The index already beats the seed

Let s(i, n) = family10 (n). At every input n:
1. The leaf stage is R11 (s, n), and child zero of the seed prefix is s(0, n) = family10 (n). Hence
family10 (n) < Ss(11) (leaf, n).
2. The first child of treesOfDepth 0 is the denotation of the default zero term, which the repository
proves is a leaf. Therefore
Ss(11) (leaf, n) < Ss(11) (treesOfDepth(0), n).
3. treesOfDepth 0 is child zero of I, so
Ss(11) (treesOfDepth(0), n) < Ss(11) (I, n).
Combining these inequalities gives the formal theorem
family10 (n) < Ss(11) (I, n).
This proof is intentionally concrete. It does not need to know the height or ordinal represented by I.

8.2

Eventual domination of every old-language tree

Suppose a raw W-language term t belongs to the depth-k enumeration, and let i be an index where
it occurs. For every n ≥ k + i, both k ≤ n and i ≤ n. The denoted tree is then a visible child of
treesOfDepth k; that join is a visible child of I; and I is strictly below the crown. Thus
Ss(11) (defTree(t), n) < F11 (n).
The threshold k + i is explicit. The Lean theorem is defined_tree_eventually_lt11.
This cofinality result is relative to the earlier W-language’s tree output. It does not claim that
kind-polymorphic programs themselves generate every tree; the current Fkω object language returns
Church numerals, not W -objects. That distinction is a natural target for a future, stronger contender.

Constructivity and totality

The proposed number is computable in principle for the same reason as the accepted predecessors,
plus two elementary structural recursions.
10

1. Finite enumeration. Fk.ctmsUpTo n is a finite list constructed recursively from finite lists of
kinds, types, and terms.
2. Decidable checking. Fk.infer is fuel bounded. Rejected terms contribute zero.
3. Total normalization. An accepted term at the Church numeral type has a proof of strong
normalization, so Fk.nf is a total Lean function on the proof-carrying term.
4. Finite maxima. Both the syntax maximum and the child-prefix maximum range over finite data.
5. Well-founded forest recursion. stage11 recurses structurally on WTree, exactly as the existing
stage9 does.
6. Primitive crown recursion. crown11 recurses on a natural number and constructs a finite unary
spine.
7. Closed specialization. contender_11 substitutes the closed numeral 42 into closed total functions.
No semantic oracle is assumed. The only oracle seen by an object-language program is a Leancomputable function generated from recursive calls on strict subtrees. The result is fantastically
infeasible, but infeasibility is not noncomputability.
Never evaluate the actual contender. Computability is certified intensionally by total
definitions and termination proofs. Attempting to normalize F11 42 would be both unnecessary
and catastrophic. The comparison proofs quantify over symbolic inputs and use finite-maximum
inequalities.

10

Why this is a qualitative advance

10.1

From one reflection to a reflection forest

Contender 10 applies the kind-polymorphic reflector once to family9 at each input. The new
construction makes that reflector the local transition at every node of a well-founded tree. At a node,
an object-language program has uniform access to all child stages through the packed oracle. The
node then exceeds all visible children and all accepted programs relative to them.
This is not equivalent to a fixed iteration count written in arithmetic. The shape of the iteration is a
W -tree whose branching can be selected by computed indices. The self-generated index ranges over
every tree output by the earlier W-language, and the crown adds a separate diagonal sequence of new
layers.

10.2

What is proved, and what is heuristic

The following claims are exact consequences of the supplied definitions and proof scripts:
• family10 (n) < F11 (n) for every n;
• C10 < C11 ;
• each crown edge is strict;

Crowned kind-polymorphic forest reflection

• all root programs in the bounded Fkω enumeration are reflected;
• every W-language-defined tree is eventually dominated.
It is reasonable to describe the move from a single Fkω reflection to Fkω reflection along a self-generated
forest as a multiplicative or iteration-level increase in proof-theoretic terms. However, this article
does not assign an exact ordinal to the kind-polymorphic language, to the forest closure, or to the
crowned diagonal. The repository’s formal inequalities are stronger evidence than an unsupported
ordinal name.

10.3

No claim of maximality

No computable description can be the last word in an unrestricted contest: a new description can
reflect or diagonalize over it. The research objective is therefore a transparent and formally comparable
advance over the actual incumbent, not a metaphysical “largest computable number.”

11

No-laziness and dependency hygiene

The computational dependency graph is designed to satisfy the repository’s no-laziness rule.
1. Contender11.lean imports BusyLean.Contender10, not BusyLean.Comparison10.
2. Its executable syntax contains no identifier contender_10.
3. The predecessor enters only through family10 n := F10 (F10 n), a uniform family subsequently
used as the leaf seed of a new forest operator.
4. The new scalar applies F11 to its own inner value, rather than adding a large but semantically inert
arithmetic constant.
The package includes a kernel-side transitive closure command modeled on the repository’s audit. It
is intended to establish that BusyLean.contender_11 avoids every earlier named scalar contender,
while still exposing all legitimate dependencies on the generic constructions. A separate static audit
strips nested Lean comments and strings before checking that contender_10 is absent from executable
definition syntax.

Potential objections and responses

15.1

“Is the crown merely padding?”

The crown supplies a transparent diagonal margin, but the entry does not rest on it. Even before the
crown, family10_lt_stage11_index shows that kind-polymorphic reflection along the self-generated
index beats the whole predecessor family. The crown then makes the number of additional semantic
levels explicit and input-dependent.

15.2

“Could Contender 10 write the same computation as one program?”

A bounded Fkω term at one reflection node may perform rich arithmetic and many oracle calls. The
new construction nevertheless encloses every listed such program in a new maximum, changes the
oracle to a family of recursively computed child stages, and repeats this operation along a meta-level
W -tree. The exact root-program and parent-edge theorems certify that structural separation without
requiring a semantic non-definability theorem for all possible encodings.

15.3

“Does the old W-language index limit the advance?”

Yes, in a precise sense: the cofinality theorem ranges over trees produced by the old W-language,
because the current kind-polymorphic object language is a numeral language. This is a limitation,
not a flaw in the comparison. A future object language with both kind polymorphism and positive
inductive W -types could generate a stronger self-index, but its normalization and large-elimination
metatheory would be a much larger formalization project.

15.4

“Where is the exact proof-theoretic ordinal?”

It is not asserted. Kind polymorphism, the precise checker, the oracle extension, forest reflection,
and diagonal crown form a concrete computable hierarchy. Calibrating that hierarchy by a standard
ordinal notation system would be valuable separate research. The BusyLean contest only needs the
formal finite inequality, which is stronger and less ambiguous than an unproved ordinal analogy.

16

Further research program

16.1

Immediate certification

The first task is mechanical but essential: run Lean 4.34.0, repair any elaboration-only issues, record
definition and proof times, and inspect the exact axiom list and dependency closure. The package
separates generic lemmas from the final scalar so that repairs should not invite numerical reduction.

16.2

A kind-polymorphic W-language

The most direct qualitative successor would internalize positive inductive families or W -types into the
kind-polymorphic language, with a normalizer and checker strong enough to support large elimination
without inconsistency. Then the self-generated index could enumerate trees produced by the same

language that performs reflection, rather than by an older predicative language. The central research
problem is to design a total calculus that is stronger than Fkω yet still admits a reducibility or
logical-relations proof within the permitted Lean axiom envelope.

16.3

Typed family oracles

The current pairing exposes a family through a unary natural oracle. A richer object language could
include a primitive family oracle or dependent oracle interface, eliminating coding overhead and
allowing typed child data. To be a contest advance rather than syntactic sugar, one would need an
exact embedding of the old interface and a program or tree not representable at bounded cost in the
old syntax.

16.4

Self-generated kind indices

Contender 10 can quantify over closed kinds but does not hand a syntactic kind index back to the
forest layer. One could study a two-sorted hierarchy whose nodes carry both W -tree branches and
closed kind codes, with reflection over all programs and type operators below a joint budget. A
diagonal index could then traverse kind order and tree order simultaneously.

16.5

Certified majorants and monotone reflection

The present proof wisely avoids oracle monotonicity. Another route is to associate each accepted
program with a certified monotone majorant. Reflection could then compare entire oracle families
extensionally and support more powerful transfer theorems. The challenge is obtaining useful majorants
for conditionals and encoded data without collapsing the object language to an obviously weaker
positive fragment.

16.6

Exact calibration

A long-term mathematical project is to identify theories whose provably total functions match the
bounded maxima of the current Fkω calculus, its oracle extension, and the forest closure. Even upper
and lower ordinal bounds would clarify which next language feature—large elimination, universes,
inductive families, or stronger recursion—produces a genuine proof-theoretic jump.

16.7

Enumeration compression

The current syntactic enumerations grow extremely quickly and use the same input as both syntax depth
and type-checking fuel. Certified binary encodings, hash-consed syntax, or direct rank enumerators
might reduce checking overhead without changing the mathematical maximum. Any optimization
must prove coverage and semantic agreement and must preserve the contest’s finite-time build budget.

audited under the pinned toolchain. All material needed for that run is included.
