Abstract
We construct a specific computable natural number by reflecting over complete semantic
libraries rather than merely over numerical outputs. A library exposes a reflection hierarchy, a
generator of well-founded trees, a common seed, a numerical input, an independent tower amplifier,
and a relative function family. The underlying raw finite-type W-language is exactly the one
already used in BusyLean. A fixed rank-17 term in this unchanged syntax reconstructs and
amplifies an older library’s entire measured construction. A new reflection operator therefore
exceeds that construction by an explicit large margin.
Structural recursion on generated W-trees is then lifted from numerical functions to whole
libraries. We join all finite self-generated bootstrap rounds and bootstrap the resulting limit
library once more. Writing C(n) for the pinned repository’s Contender-6 family and N(n) for
the resulting family, we prove B◦(n+2)(C(n)) < N(n), where B(x) = x + 1 + T(x + 1, x + 1)
and T(h + 1, x) = 2T (h,x). Thus the proposed entry N(42) exceeds 44 successive self-sized tower
amplifications of Contender 6. A stronger qualitative theorem gives eventual domination and
non-representability in every finite predecessor library, and also in the limit library. The package
supplies a standalone Lean implementation proposal, full mathematical proofs, an independent
executable reference model, exact source provenance, and validation scripts.
Verification boundary. The mathematical arguments are given in this report. The newly supplied
Lean source has not been compiled: no Lean executable was available in the generating
environment. Python tests and upstream source-hash checks passed. Kernel acceptance, axiom/de-
pendency audits, and the contest’s compilation-time budgets remain unexecuted. This is a research
proposal with proof source, not a certified contest admission.

1
The target and the nature of the advance
The baseline is the current adopted Contender 6 at the pinned BusyLean commit [1, 4], not merely the
earlier Coq Contender 5. Its central ingredients are a total interpreter for finite types with W-types,
reflection relative to a countable family of functions, and an index joining all trees produced by the
language. The repository already provides exact comparisons with Contender 5 and proposal P5 [5].
Simply rebuilding a System-T maximum, or adding an arithmetic operation to the earlier contender,
would not address the actual target.
The present construction changes the level at which reflection operates. An older stage is made
available as a library of higher-order operations. Programs may supply it with arbitrary seeds and
trees, generate new trees using it, and combine it with the other operations in the original language.
The next stage takes a finite maximum over this enriched semantics. In particular, it exceeds a
short program that reconstructs the older stage’s completed measurement, but that one comparison
program is only a small part of what is being reflected.
There are two independent distinctions to keep clear. First, the numerical inequality proved
here is much stronger than C6 + 1 < N, but it is only a conservative lower bound on a semantic
construction. Second, a mathematical proof in an article and a successfully checked Lean proof are
different artifacts. We provide the first and source intended to implement it; we do not claim the
second has been obtained in this environment.
1.1
Precise comparison coverage
The direct mathematical comparison is against the pinned adopted C6, uniformly in its input. C5 and
P5 then follow by transitivity using the repository’s existing comparisons; a separate integration file
records these two steps. The repository also retains proposals P1–P4, whose ranking in the upstream
review uses informal ordinal estimates [6]. This report does not silently turn those estimates into
exact finite-number theorems. Separate rigorous comparisons with those archived proposals remain
an integration task. No claim is made to exceed every arbitrary auxiliary constant or every future
addition to the repository.
The repository’s stated rules require a constructive closed natural-number term, restrict axioms to
propext and Quot.sound, prohibit the usual noncomputable or unchecked escape hatches, and impose
15-second and 60-second clean definition/proof budgets under Lean 4.34.0 [1]. The construction is
designed for these rules. Its actual compilation and budget compliance remain to be tested.

The inherited language and the exact baseline
2.1
Finite types with well-founded branching
The inherited type syntax is
A ::= nat | A →A | wt A.
Its interpretation satisfies

JA →DK = JAK →JDK,

Only the countably branching type T = W(N) is needed for the outer schedules, but the interpreted
language retains W-types over every one of its finite types. Its raw terms have nine constructors:
variables, typed lambdas, application, zero, successor, natural recursion, W-leaf, W-node, and W-
recursion. All definitions are taken unchanged from the repository’s P5 language implementation [2].
Values are dependent pairs (A, v) with v ∈JAK. The interpreter is total on raw, possibly ill-typed
terms: unsuccessful applications or casts follow the repository’s default-value conventions. We do not
replace these conventions with a different dynamic semantics. This matters because the baseline is a
maximum over raw terms, not merely a maximum over well-typed terms.
The function allTerms(d) is a finite list built structurally in d. Type annotations, variable levels,
and all term constructors are bounded by the same enumeration-depth parameter. We use this exact
enumeration throughout. There is no filter for semantic totality and no halting test.

4.2
Same-type W-casts are not judgmental identities
The upstream cast from W(A) to the same W-type applies a branch reindexing map. Even if the
map on A is an identity, the resulting tree is not in general definitionally the original arbitrary tree.
This is a genuine proof engineering issue, not a numerical discrepancy.
Lemma 4.1 (Identity reindexing). For every type X and every t ∈W(X), wmap(id, t) = t exten-
sionally.
Proof. Use W-induction. The leaf case is the defining equation. For t = nodef, the left side is
node(x 7→wmap(id, f(x))). The induction hypotheses identify every branch with f(x). Function
extensionality identifies the branch functions, and congruence identifies the nodes.

Lemma 4.2 (Same-type cast identity). For every finite type A and v ∈JAK, the original
castValue(A, v) is extensionally equal to v.
Proof. Prove both directions of the original castPair(A, A) together by induction on A. For nat both
functions are identities. The arrow case composes the already-identity domain and codomain casts,
and the Boolean same-type test is true by structural induction. The W-case invokes Lemma 4.1 after
the branch-type induction hypothesis. Projecting the first component proves the statement.
This use of function extensionality is compatible with the stated allowance of Quot.sound; it is
not an assertion that the resulting axiom audit has already been executed. The numerical definitions
do not depend on these cast-equality proof terms.

This separation avoids an invalid argument: pointwise increasing a function family need not

neither conclusion about the whole maximum: it retains the relevant semantics exactly.

Computability and well-foundedness
The word “computable” should do real work in a large-number proposal. It is not enough to observe
vacuously that any particular natural number could be printed by some program. Here there is an
explicit uniform, terminating construction of the family N(n) from the given finite definitions.
Proposition 8.1 (Constructive closure of the model operations). The initial model is computably
presented. A uniformly computably presented family of models has a computably presented join. Given
a computably presented model and tree, its model fold is computably presented. Consequently every
finite bootstrap round, the limit model, the final model, and N(n) are computable in principle.
Proof. The inherited raw interpreter recurses structurally on finite syntax. Its natural and W recursors
are total recursors; its cast operation recurses on finite type syntax and, where necessary, on W-trees.

The shared seed uses only these operations and structural recursion on natural iteration counts. Thus
the initial reflection algebra and tree generator are computable from finite input descriptions.
For a join, the numerical reflection component enumerates finitely many indices i ≤n and finitely
many raw terms of depth n + 17. Every term is interpreted in a computably supplied library. There
is no search for a proof of termination, and no wait for an unspecified program to halt. The tree
component creates a W-node with a computable branch function; to request branch j is to interpret
one specified term in one specified child library. Creating such a branch function does not require
listing all its values.
The fold in (18) is precisely the recursor of W(N) with result type M. Its recursive arguments
are the results at the immediate subtrees f(i). The guarded index is built from the already-given
generator of m, before this fold is invoked. It does not call the bootstrap being defined. Thus
bootstrapping is composition of total functions followed by a structural recursion, not a circular
fixed-point definition.

A countably branching W-tree may have an enormously complicated shape, but its inductive

8.1
What is not being used
The numerical construction does not use a Busy Beaver oracle, a semantic predicate selecting all total
Lean programs, a nonconstructive maximum, or a universal interpreter for the language containing
its own full semantics. Every finite maximum ranges over the old fixed raw syntax. The increase in
strength comes from a hierarchy of explicitly built semantic libraries. Nor is there a partial-function
shortcut that supplies a default numerical answer to an unproved termination problem.
All supplied numerical source is ordinary def code. The source scan finds no prohibited escape-
hatch tokens outside comments and strings. A stronger transitive axiom/dependency audit is provided
separately because a lexical scan alone cannot establish those properties.

The explicit tower separation
Lemma 9.1 (Elementary amplifier properties). For all natural x, x < B(x). Also, a ≤b implies
B(a) ≤B(b). Consequently x ≤B◦k(x) for every k.
Proof. The first assertion follows from the summand x + 1. Exponentiation by two is monotone
and satisfies y < 2y for all natural y, including zero. Induction on the tower height therefore shows
monotonicity in its top argument. The inequality T(h, x) ≤T(h + 1, x) follows from y < 2y with
y = T(h, x); iterating it gives monotonicity in the height.
If a ≤b, then

Add the monotone term a + 1 ≤b + 1. Finally induct on k, using x < B(x) at the inductive step.

9.1
Why “44” is not an arbitrary advertised height
The number 44 is a count of repeated self-sized tower transformations. At each application of B, both
the tower height and its top argument are chosen from the already enormous previous value. It is not
a tower of fixed height 44. The count comes from 42 bootstrap rounds visible in the limit comparison,
one reflection at the limit join, and one more final bootstrap.

9.2
The proof avoids numerical normalization
Every substantial theorem is proved for abstract m, n before being specialized. The final comparison
with 42 is merely an application of the uniform theorem. A checker should never need to reduce
C(42) or N(42). The same principle governs compiler correctness: it is first proved for abstract
h, g, s, n, a, f. Replacing those variables by concrete giant semantic objects inside a simplification
proof would invite catastrophic evaluation.

What is new here, and what is deliberately not claimed
The construction combines three ideas in a concrete package: a constant-cost compiler for a full
preceding hierarchy measurement, a structural tree fold whose outputs are whole semantic models, and
a further traversal through the trees generated by the limit library itself. The resulting comparison
and non-representability arguments are exact and avoid ordinal calibration. This is the proposed
contribution of this report; a broad literature-priority claim has not been established.
The root compiler theorem already proves a strong lower bound even if one ignores much of the
elaborate generated-tree schedule. That is a virtue for verification, but it also sets a boundary on
what has been proved. We have not identified an exact ordinal for the whole construction, proved
a sharp fast-growing-hierarchy equivalence, or quantified the additional advantage contributed by
every nonzero generated-tree branch. The non-representability theorems concern the actual enriched
libraries and are stronger evidence of structural separation than an unsupported ordinal label would
be.
The new entry is not a claimed largest computable number. Once its description has been fixed,
larger computable descriptions can be made. The relevant achievement is a substantial, reproducibly
specified advancement over the actual current benchmark, together with the proof obligations that
make the comparison meaningful.

Further research questions
1. Complete the machine validation and minimize proof cost.
The immediate task is to
run Lean 4.34.0, repair any elaboration issues without changing the semantics, and collect actual
dependency and timing evidence. Replace broad simplification with explicit parametric interpreter
lemmas where needed. This is an essential completion criterion, not a claim of an already finished
formalization.
2. Compile all archived proposals into an exact comparison library.
Produce translations
or exact semantic embeddings for P1–P4, with explicit syntax costs and finite-input bounds. This
would replace the review’s heuristic ranking by exact comparison theorems and close the remaining
scope gap in this package.
3. Quantify the extra strength of generated-tree branches.
The certified tower margin uses
a deliberately easy visible branch. Prove lower bounds that exploit nonzero generated-tree branches,
rather than merely the predecessor guard. A useful starting point is an address-preserving simulation
relation on model-valued folds, designed to preserve exact library semantics rather than pointwise
approximate arbitrary oracles.
4. Find the smallest effective compiler overhead.
The current fixed program has rank 17.
Alternative environment layouts, index encodings, or typed compilation may lower this cost. Prove
optimality only relative to an explicit encoding and allowed library signature; a shorter-looking
informal lambda term is not by itself an enumeration-depth certificate.
5. Separate semantic strength from numerical amplifier choice.
Generalize the construction
to an arbitrary supplied monotone expansive amplifier A. The same compiler and maximum argument
should yield A◦(n+2)(C(n)) < NA(n) with unchanged syntax rank. This isolates the semantic-library
advance from the chosen elementary tower certificate. The parametric compiler theorem already
supplies most of the needed proof.
6. Develop a typed front end with a semantics-preserving raw translation.
An intrinsically
typed representation could simplify compiler proofs and avoid repeated cast reasoning. It must
translate into the exact existing raw interpreter with explicit rank control, rather than replacing the
baseline semantics silently. A logical relation would be a natural tool for this task.
7. Study reflection monotonicity precisely.
Determine which restricted program fragments
admit oracle monotonicity and whether any monotone envelope of the full finite maximum is
useful. The individual zero-test counterexample does not settle monotonicity of the whole maximum.
A theorem addressing that distinction could support sharper tree comparison methods without
compromising the current exact-library argument.
8. Seek calibrated, conditional ordinal bounds.
Only after fixing a precise notation system,
fundamental sequences, and simulation theorem should one attach a fast-growing-hierarchy label to
this construction. Such a result would be explanatory; it is not needed for the exact comparisons proved
here. A credible calibration must account for both the interpreted language and the model-valued
bootstrap layer.

Conclusion
The proposed number is specified by a finite, constructive chain of semantic operations. Its strongest
established mathematical feature is not merely its 44-fold self-sized tower margin over the adopted
Contender 6, but its eventual separation from every fixed program in each finite predecessor library
and from every fixed program in the limit library. The entire mechanism uses the existing W-language
with richer executable environments, and all numerical maxima remain finite.
The report separates this mathematical achievement from the uncompleted machine-verification
step. The source, exact dependency snapshot, independent tests, and reproducible checks make
that remaining step concrete and inspectable. The resulting package is a substantial proposed
advancement over the current benchmark, with neither an unsupported optimality claim nor an
invented kernel-verification claim.

C
A general amplification schema
The specific tower amplifier is not essential to the semantic mechanism. Let A : N →N be a
computably defined monotone function with x < A(x) for all x. Replace only the level-4 library value
B by A, and use the same rank-17 syntax pB (now better named pA). The parametric compiler lemma
gives EA(m, f, n, pA) = A(νm(n)) without altering its rank. Repeating the finite-max, bootstrap, and
round proofs gives
A◦(n+2)(C(n)) < NA(n).
The constant A must itself be explicitly computable and must be included in any definition-size and
compilation audit. It is not legitimate to insert an uncomputable “ideal amplifier” and retain the
computability conclusion. This general statement is proved by the same mathematical argument;
the packaged final number fixes A = B and the Lean comparison modules are written for that fixed
choice.
The schema explains why iterating a numerical transformer is a useful certificate rather than a
complete description of the new number. Changing A changes a library value, but the surrounding
reflection still ranges over arbitrary programs using the complete prior hierarchy and its generated
trees.
